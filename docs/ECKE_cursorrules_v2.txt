# ECKE Platform - Cursor Rules v2
## Self-Contained Event Listing (Org Self-Signup + Auto-Publish Events)

You are helping build ECKE, an independent event listing platform where organizations self-signup, create/manage events, and events appear immediately on the public site.

## PLATFORM SCOPE

**What you're building:**
- Org self-signup with username/password login
- Org dashboard for creating/editing/deleting events
- Public discovery pages (browse, search, filter events)
- Password recovery via email
- SEO-optimized event detail pages

**What you're NOT building:**
- Event approval workflows
- Ticketing or registration system
- Multi-staff org logins
- Syncing with kink.social or other platforms

## TECHNOLOGY STACK

- **Framework:** Next.js 14 with App Router
- **Language:** TypeScript
- **Database:** Supabase (PostgreSQL)
- **Auth:** JWT tokens (stateless)
- **Password:** bcrypt for hashing
- **Styling:** Tailwind CSS
- **Editor:** Tiptap for rich text (optional)
- **Deployment:** Vercel

## AUTHENTICATION FLOW

### Org Signup
```
User visits /auth/org/signup
Fills form: org name, email, website (optional), username, password
POST /api/auth/org/signup
  1. Validate input (Zod schema)
  2. Check username not taken
  3. Check email not taken
  4. Hash password with bcrypt
  5. Create organizations row
  6. Create org_credentials row
  7. Generate JWT token (24h expiry)
  8. Return token + org info
Browser stores token in localStorage
Redirect to /dashboard
```

### Org Login
```
User visits /auth/org/login
Fills form: username, password
POST /api/auth/org/login
  1. Look up org_credentials by username
  2. Compare password with bcrypt
  3. Update last_login timestamp
  4. Generate JWT token
  5. Return token + org info
Browser stores token in localStorage
Redirect to /dashboard
```

### Password Recovery
```
User visits /auth/org/recover-password
Enters email → POST /api/auth/org/recover-password
  1. Find org_credentials by email
  2. Generate reset token (JWT, 1h expiry)
  3. Send email with reset link
  4. Return success message
User clicks link in email → /auth/org/reset-password?token=...
Form submits new password → POST /api/auth/org/reset-password
  1. Verify reset token
  2. Hash new password
  3. Update org_credentials.password_hash
  4. Return success
User can now login with new password
```

### JWT Token Structure
```typescript
{
  orgId: string,
  iat: number,
  exp: number
}
```
Stored in localStorage as `ecke_token`. Sent in Authorization header for protected APIs.

## PROTECTED ROUTES

These pages require valid JWT token:
- `/dashboard` - org dashboard
- `/dashboard/events/create` - create event form
- `/dashboard/events/[eventId]` - edit event form

Check token on page load:
1. Retrieve from localStorage
2. Verify signature + expiration
3. If invalid, redirect to `/auth/org/login`

## EVENT CREATION FLOW

Org must be logged in to create events.

### Form (single page or multi-step):

**1. Basics**
- title (required, 5-500 chars)
- type (select: Convention, Workshop, Dungeon, Social, Class)
- slug (auto-generate from title, allow edit, check for duplicates)

**2. Description**
- description (plain text, 20-5000 chars)
- rich_description (optional, Tiptap editor output as JSONB)

**3. Location**
- location_name (optional)
- address (optional)
- city (required)
- state (required, 2 chars)
- zip_code (optional)
- region (required, e.g., "Southeastern United States")
- latitude, longitude (optional or auto-geocoded)

**4. Timing**
- start_date (required)
- start_time (optional)
- end_date (optional)
- end_time (optional)
- date_status (select: confirmed, tba, tentative)
- recurring toggle (optional)
- recurrence_rule (optional, if recurring)

**5. Details**
- age_restriction (select: 18+, 21+, none)
- dress_code (optional)
- expected_attendance (optional, integer)
- entry_fee (optional, decimal $0.00)

**6. Media**
- cover_image_url (required, upload to Supabase Storage)
- gallery_urls (optional, max 5 images)

**7. Contact**
- contact_email (pre-fill org email, can edit)
- contact_phone (optional, e164 format)
- official_website (optional, valid URL)

**8. Tags**
- tags (array of strings, max 10)
- pre-defined options: BDSM, Rope, Impact, Furniture, Bondage, Submission, Dominance, Social, Education, Dungeon, Convention, Workshop, Beginner-Friendly, etc.
- allow custom tags (not just pre-defined)

**9. Publish**
- Save as Draft button → status='draft'
- Publish button → status='published', published_at=now()
- Preview button → shows /events/[slug] as it will appear
- Delete button (if editing existing event)

### Form Validation (Zod)
```typescript

    endTime: z.string().optional(),

  }),

    dresCode: z.string().optional(),
    expectedAttendance: z.number().int().positive().optional(),

```

### Event Publishing
When org clicks "Publish":
- POST /api/events (create) or PUT /api/events/[eventId] (update)
- Include `status: 'published'` and `published_at: new Date()`
- Event appears immediately on public site at `/events/[slug]`
- Org can see it in their dashboard

### Event Editing
Org can edit published or draft events:
- Click event in dashboard → /dashboard/events/[eventId]
- Form pre-populated with existing data
- Can change any field
- Can change status (published → draft, vice versa)
- Can delete entirely

### Event Deletion
Org can soft-delete or hard-delete:
- Option 1: Set status='archived' (soft delete, can restore)
- Option 2: DELETE from database (hard delete, permanent)
Recommendation: Soft delete for safety, hard delete on user request.

## CODE QUALITY STANDARDS

### TypeScript
- Strict mode enabled
- No `any` types without justification
- Use interfaces for data models
- Type all function parameters and returns

### Components
- Functional components only (no class components)
- React hooks for state management
- Proper error boundaries and error states
- Loading states for async operations
- Accessible (ARIA labels, semantic HTML)

### API Routes
- Input validation before processing (Zod)
- Proper error responses (400, 401, 404, 500)
- CORS if needed
- Rate limiting for sensitive endpoints (signup, login)
- Never expose internal error details to client

### Database Queries
- Always use Supabase parameterized queries
- Never concatenate user input
- Include necessary JOINs in RLS policies
- Index frequently queried columns

## WHEN IMPLEMENTING

### For Auth
- Use bcrypt for password hashing (npm install bcrypt)
- Generate JWT with secret from .env
- Store JWT in localStorage (clear on logout)
- Verify JWT on protected page load
- Handle token expiration gracefully

### For Events
- Slug must be unique (enforce in database unique constraint)
- Pre-fill org_id from logged-in session
- Allow image uploads to Supabase Storage bucket
- Show preview before publishing
- Support draft/published states

### For Forms
- Use React Hook Form for form state
- Use Zod for validation (client + server)
- Show validation errors inline
- Disable submit button while submitting
- Show success/error toasts after submit

### For Pages
- Add generateMetadata for SEO (all public pages)
- Add JSON-LD schema for events
- Use next/image for responsive images
- Implement ISR (revalidate after publishing event)
- Handle 404 gracefully (event not found, org not found)
